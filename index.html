Interlude · failure modes

Every failure has a defined response.

The workflow never fails silently. Each stage answers with its own HTTP status and a machine-readable body — the exact bodies from the workflow:

400 · INVALID ORDER

Validation fails, nothing happens

The webhook answers immediately. No sheet write, no email. The body lists every broken rule so the sender can fix and resend.

{ "status": "rejected", "errors": [ "customer_email must be valid", ... ] }

502 · SHEETS FAILURE

The write fails, silence is safer

The spreadsheet write fails → no notification is sent, so the owner is never told about an order that was not stored. Safe to retry with the same order_id.

{ "status": "error", "stage": "google_sheets", "message": "Order storage failed; use the same order_id for a safe retry." }

502 · GMAIL FAILURE

Stored, but not announced

Email fails after the sheet write → the order is already stored. The partial-failure flag warns you to check notification state before retrying.

{ "status": "partial_failure", "stage": "email", "saved": true, "notified": false, "message": "Order stored but notification failed..." }
